# Trademarks

The specification and code in this repository are licensed under the [Apache License 2.0](LICENSE). That licence
covers the work; it does not grant rights to the project's names (Apache 2.0, section 6).

"Veridact" and "Veridact Valet" are names held by Richard Craig. They are kept separate from the code so that
banks, agent operators and customers can trust what carries them.

## What you can do without asking

- Use, run, modify and redistribute the code and specification under Apache 2.0.
- Say truthfully that your product "implements the Veridact specification", "verifies Veridact credentials" or
  "passes the Veridact conformance vectors" (naming the version).
- Refer to the project by name in articles, talks, comparisons and documentation.

## What needs permission

- Naming a product, service, fork, issuer or company "Veridact", or something confusingly similar.
- Calling an issuer "Veridact" or "a Veridact issuer" unless the governance authority's trust list accredits it.
- Using the name or logo in a way that suggests the project endorses, certifies or operates your product.
- Claiming certification before a public certification programme exists.

## Forks

You are free to fork. A fork that changes verification, issuance or trust rules must use a different name, so
nobody mistakes it for the reviewed specification.

## Contact

Ask through a GitHub issue. Permission is not unreasonably refused.

## Future

If the project joins a neutral foundation, or the governance authority is formed, the names may be transferred
under that body's trademark policy. That decision belongs to the steering group (see [GOVERNANCE.md](GOVERNANCE.md)).
