# Proposed changes for v0.2: gaps found building the verifier

Status: **accepted** · 9 November 2026 · incorporated into [specification v0.2](../specification.md)

> Item 7 was adjusted when incorporated: a status list's `exp` is at most **4 hours** after `iat`, not 15 minutes.
> A 15-minute `exp` would have made cached lists unusable after 15 minutes, contradicting the degraded-mode table,
> which allows cached status for up to 4 hours. Re-signing every 5 minutes and measuring age from `iat` are unchanged.

Building `veridact-verify` against v0.1 turned up places where a verifier has to make a choice the spec does not
make. Each item below states the gap, what the reference verifier does today, and the text proposed for v0.2.
The conformance vectors in [`conformance/`](../../conformance) encode these choices, so changing one means
regenerating the vectors.

## 1. Delegation limits in the Agent Credential

**Gap.** Relying parties must enforce per-payment and daily limits and return `LIMIT_PER_PAYMENT` or
`LIMIT_PER_DAY`, but the Agent Credential has no claim that carries the limits.

**Verifier today.** It reads `credentialSubject.limits`:

```json
"limits": { "currency": "ZAR", "perPayment": "500.00", "perDay": "2000.00" }
```

Amounts are decimal strings, so no implementation loses cents to binary floating point. If the relying party
checks a payment and the credential has no limits in that currency, the result is `ask_person` with
`LIMIT_PER_PAYMENT`: no delegated limit means no authority to pay alone. The verifier holds no ledger. The
relying party passes what it has already let the agent pay today.

**Proposed text.** Add `limits` to the Agent Credential's key claims, copied by the issuer from the Delegation
Credential and capped by the approver's ceiling. Absent limits mean the agent may not pay without a person.

## 2. Status entry on the Operator Credential

**Gap.** Check 5 says "both status list entries", but the Operator Credential's claims do not list a
`credentialStatus`.

**Verifier today.** The verifier requires a `BitstringStatusListEntry` on both credentials. A relying party can turn
off the operator requirement (`require_operator_status=False`) during migration.

**Proposed text.** Add "status entry" to the Operator Credential's key claims. Revoking an Operator Credential must
take effect within 5 minutes, the same as for an agent, because otherwise a 12-month Organisation-tier credential
has no fast kill switch.

## 3. Trust list schema

**Gap.** The spec names the trust list's location and contents, but not its claim names. Two verifiers could read
the same list differently.

**Verifier today.** A compact JWS with `typ: trust-list+jwt`, signed by a governance key the relying party pins as
a JWK (never resolved through a DID, so a DID host compromise cannot change the root):

```json
{
  "iss": "https://trust.veridact.net",
  "version": "2026.11.1",
  "iat": 1794124800, "exp": 1794816000,
  "issuers": [{
    "id": "did:webvh:…:veridact.net:issuers:org-2026b",
    "tiers": ["domain", "organisation"],
    "credentialTypes": ["VeridactAgentCredential", "VeridactOperatorCredential"],
    "keys": [{ "kid": "did:webvh:…#key-3", "notBefore": 1789027200, "notAfter": 1796803200 }]
  }],
  "scopes": ["fs:claims:read-status", "fs:quotes:create", "fs:payments:initiate"],
  "policy": {
    "tierOrder": ["domain", "organisation"],
    "agentCredentialMaxLifetime": 86400,
    "presentationMaxLifetime": 120,
    "operatorCredentialMaxLifetime": { "domain": 7776000, "organisation": 31622400 }
  }
}
```

Rules the verifier applies:

- **Key epochs.** `notBefore` and `notAfter` bound when a key may *sign*. A credential is accepted if its `iat` falls
  inside its key's window. This lets a 12-month Operator Credential outlive the 90-day key rotation. Removing a key
  from the list, for example after compromise, invalidates everything it signed.
- **Rollback.** A verifier refuses a list whose `iat` is older than one it has already accepted, so a stale mirror
  cannot restore a removed issuer.
- **Stale use.** A cached list may be used after a failed refresh until its own `exp`, never beyond.
- **Scopes.** Credential scopes outside `scopes` are dropped, not treated as a failure.
- **Emergency lifetime extension** is a change to `agentCredentialMaxLifetime`.

Witnesses, transparency logs and validators are left out of this first schema because the verifier does not yet
use them.

**Proposed text.** Adopt this schema as normative in "Trust registry and governance hooks".

## 4. Enveloped credentials in the presentation

**Gap.** The spec says the presentation carries "enveloped Agent and Operator Credentials" but not the encoding.

**Verifier today.** It follows VC-JOSE-COSE. `verifiableCredential` is an array of objects with
`type: EnvelopedVerifiableCredential` and `id: data:application/vc+jwt,<compact JWS>`. The holder is `holder` (the
agent DID), and `kid` in the protected header must be one of the agent DID's `authentication` keys. Exactly one
Agent and one Operator Credential are required. Bare JWT strings are rejected.

**Proposed text.** State this encoding, and give a decoded Agent Presentation alongside the decoded Agent
Credential.

## 5. Public codes for outages and operator policy

**Gap.** Two decisions have no public code in v0.1:

- Verification could not finish because the trust list, a DID log or a status list could not be fetched and no
  usable cached copy exists, or because degraded-mode policy blocks the action. `AUTH_FAILED` would be wrong, because
  it tells the caller to give up when it should retry.
- The relying party's policy does not accept this operator.

**Verifier today.** It returns `VERIFICATION_UNAVAILABLE` (deny; caller retries later) and `OPERATOR_NOT_ALLOWED`
(deny; the relying party has not onboarded this operator).

**Proposed text.** Add both to the reason code table.

## 6. Revoked and suspended credentials

**Gap.** v0.1 has no public code for a revoked credential.

**Verifier today.** It returns `AUTH_FAILED`, with `STATUS_REVOKED` or `STATUS_SUSPENDED` in the logs. A revoked
agent's operator already knows why, and telling an attacker that a stolen credential has been revoked helps the
attacker more than the operator.

**Proposed text.** Say explicitly that revocation and suspension map to `AUTH_FAILED`.

## 7. Status list freshness and identity

**Gap.** The degraded-mode table depends on "status list age", which can mean time since the verifier last
fetched the list or time since the issuer signed it. With the first meaning, a mirror serving a week-old list
looks fresh.

**Verifier today.** Age is time since the verifier's last successful fetch. If a list carries `exp`, the verifier
refuses it after that time. A list must name its own URL in `id` (or `credentialSubject.id` as `{url}#list`), so a
genuine list cannot be served in place of another.

**Proposed text.** Issuers re-sign each status list at least every 5 minutes with `exp` no more than 4 hours
after `iat` (originally 15 minutes; see the note at the top), and verifiers measure age from the list's `iat`. That makes the degraded-mode table mean the same thing
everywhere and makes stale mirrors detectable.

## 8. Order of checks 3 and 4

**Gap.** Checking signatures (3) before accreditation (4) means resolving whatever issuer DID a presentation
names, which lets a caller make the verifier fetch arbitrary URLs.

**Verifier today.** Before resolving an issuer DID, it confirms that the trust list names the issuer. If not, it
stops with `ISSUER_NOT_LISTED`, reported as check 4. The agent's own DID still has to be resolved, so deployments
should restrict outbound fetching (see the verifier README).

**Proposed text.** "Before resolving an issuer DID, the verifier confirms the trust list names it."

## 9. Nonce consumption

**Gap.** Check 1 says the nonce must be unused, but not when it becomes used.

**Verifier today.** Check 1 confirms the nonce is live without using it. The verifier consumes it atomically only
after the presentation signature verifies (check 2). An attacker who sees a nonce cannot burn it with a junk
presentation, and two parallel replays cannot both succeed.

**Proposed text.** State this.

## 10. Tier ordering between the two credentials

**Gap.** Nothing stops an Organisation-tier Agent Credential from pointing at a Domain-tier Operator Credential.

**Verifier today.** It rejects an Agent Credential whose tier ranks above its Operator Credential's
(`OPERATOR_TIER_BELOW_AGENT`, `AUTH_FAILED`).

**Proposed text.** Add this to check 7.

## Smaller edits

- Trust model: "Issuers vouch for organisations … it never vouches" should read "they never vouch".
- Check 1: "expires within 120 seconds" is read as `exp − iat ≤ 120`, and `now ≤ exp`, with a configurable
  clock-skew allowance (default 30 seconds).
